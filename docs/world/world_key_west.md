> **Живой документ мира.** Единый реестр того, *чем Ки-Уэст является в Hoarbound* —
> атрибутика, которую автор хочет видеть в игре, наполняется по ходу разработки.
> Соседи: `KEY_WEST_FIRST_EXIT.md` (маршрут) и `WORLD_PROFILES.md` (рантайм-связки).

>   авторский геймплей ложится *поверх*.
> - **[game]** — авторский атрибут, решение по игровому миру. `← автор` = слот ждёт решения.

## 1. Идентичность

- **[game]** Мир Hoarbound — **замёрзший Ки-Уэст после климатической катастрофы**:
  самый южный город континентальных США, скованный льдом и метелью.
- **[game]** **Одна строка ощущения:** всё окружение непривычное — пёстрые дома с
  пальмами, утонувшие в снегу и инее; **холод чувствуется через экран**.
- **[game]** Что делает это именно *этим* местом, а не абстрактной снежной картой:
  сквозь снег всё ещё читаются реальная сетка улиц, аэропорт, марины и дамбы.

## 2б. Рамка мира: snapshot vs playable world  *(решение автора)*

**Правило.** Географический **snapshot может быть шире playable world**. **Playable
boundary не должен совпадать с очевидным прямым срезом DEM/OSM.** Нужен не «больше
мир», а нормальная рамка вокруг мира.

**Текущая проблема.** Кроп режет силуэт прямой границей данных: северный край и
восточный подход к Boca Chica обрезаны по рамке. (Границы: X −6601…+6603 м,
Z −3285…+3287 м; север = край Z = −3285, восток = край X ≈ +6603.)

**Пасс macro-world framing (следующий мировой проход):**
1. **Расширить кроп на север / СЗ** на ~0.5–1 км за текущую северную границу, чтобы
   береговая линия и соседние куски суши заканчивались в кадре естественно. Не
   обязательно делать играбельным. Потом посмотреть, сколько реально нужно.
   (Пересбор из NOAA-мозаики офлайн-билдером; высоты не авторятся — правило §2.)
2. **Восток — разрушенный мост как граница.** Оставить кусок подхода к Boca Chica,
   связь оборвать **внутри мира**: пролёт отсутствует, опоры торчат изо льда, дальше
   виден фрагмент дороги/суши. Boundary становится частью мира, а не техническим краем.
3. **Boca Chica — только силуэт.** Не тащить полноценный город: terrain + coastline +
   несколько крупных массингов, без городской генерации и без Тир-1. Обещание
   продолжения мира, не играбельная зона.

**Мост — слои [geo]/[game] (исходные данные не ломаем):**
- **[geo]** мост/дорога Stock Island → Boca Chica существуют в снапшоте (US-1 / Overseas Hwy);
- **[game]** после катастрофы связь разрушена (нет пролёта, опоры изо льда, фрагмент дороги за разрывом);
- исходная геометрия остаётся **reference truth**;
- разрушенная версия накладывается поверх как **authored world state** (не правит NOAA/OSM).

```

   |
```

**Порядок:** §6 (ориентиры) идёт **после** этого пасса — на целом силуэте станет видно,

Трекинг: **#208** под #138 (правило #138 — каждый мировой пасс = своя задача).

## 3. Зима

- **[game]** **Модель зимы — как сибирская зима.** Настоящий холод, а не декоративный снежок.
- **[game]** **Снег vs лёд:** суша и **кромка берега — ещё в снегу**, **дальше, за кромкой,
  — лёд** (замёрзшее море/залив). Лёд за берегом — проходимая поверхность вдали.
- **[game]** **Тонкий лёд у края** — опасность, но это **поздний срез** (не First Exit).
- **[game]** **Снег — это поле глубины (`snow_depth`), а не геометрия.** Ветер
  перераспределяет значения, не трогая меш. Пример: дорога ~0.08 м, газон ~0.35 м,
  подветренная сторона стены ~0.65 м. Подветренные сугробы — значимые (меняют
  проходимость и где прячешься от ветра). Детали архитектуры — §3а.
- **[game]** **Подпись-кадр инея/наледи (кадр идентичности):** толстый иней/наледь на
  пёстрых фасадах и пальмах, сосульки с крыш, вмёрзшие в лёд лодки в маринах (связь со
  снегом/инеем, #16/#156).
- **[geo→game]** Городское ветровое поле и стримящийся снег уже есть; экспозиция должна
  выводиться из реального массинга зданий и береговой линии, а не рисоваться декором.

## 3а. Архитектура слоёв мира: BASE / STATIC / DYNAMIC  *(решение автора)*

**Принцип.** Blender = **чистая физическая основа мира**. Снег кладётся сверху
**отдельными слоями**. **Снег никогда не запекается в топологию террейна** — иначе
смена глубины снега = смена геометрии мира (тупиковая связка на 13×6 км).
Согласовано с `SNOW_COVER.md` (#16): по мешу террейна снег не пишется, геометрия не
деформируется; наземный снег — отдельный слой/локальная оболочка вокруг игрока.

**Жёсткий тест пайплайна:** BASE WORLD должен играться с **полностью выключенным снегом**.

```
BASE WORLD            NOAA terrain · дороги/бордюры · здания · руины · пирсы ·
(Blender, authored)   крупные завалы · крыши · коллизия
        ↓             постоянные ледяные наросты — только если часть модели и
                      никогда не деформируются; база НЕ «летняя» (без травяных
                      бугров, которых зимой быть не должно), но и снег — не топология
STATIC WINTERIZATION  снег на дальних крышах · большие сугробы у недоступных зданий ·
(Blender / procedural)снежные шапки Тир-0 · сосульки · вмёрзшие лодки · дальние массы
        ↓             презентация через контракт #16: `snow_cover` (settled) +
                      `frost_amount` (иней); единственный писатель — SnowPresentationSystem
DYNAMIC SNOW          поле глубины `snow_depth` · ветровой намёт/эрозия · следы ·
(runtime, отдельно)   утоптанность · локальная деформация ТОЛЬКО оболочкой ~20–50 м
                      вокруг Генри (иначе память/GPU); за радиусом — обычное
                      представление глубины/материала = «local snow shell» = #197
```

**Снег по тирам застройки (из §5):**
- **Тир-0** — снег почти полностью статический/процедурный (игрок не ходит → дорогая
  деформация бессмысленна);
- **Тир-0.5** — деформация только на доступной земле / крыльце / навесе;
- **Тир-1** — полная локальная реакция: следы, утоптанность у входа, расчистка, намёт у стен.

**Связь с планом:** BASE + STATIC собираемы сейчас (шаги 6–7); DYNAMIC-депт-поле с
ветровым намётом — часть презентации шага 7; **локальная деформация вокруг Генри = #197
(заморожен → шаг 10)**. Блендер-билдеры трогают только BASE и крупные постоянные формы STATIC.

## 5. Застройка: разруха и интерактивность  *(ключевое решение)*

**Проблема (автор).** На карте очень много домов (**12 354** футпринта). Нужен образ
разрухи — сгоревшие, обрушенные дома — но **без ручной работы с огромным массивом**;
в каждом районе интерактивны лишь несколько домов.

**Решение — два тира зданий.** Приём проверен выживачами (в т.ч. The Long Dark): почти
все здания — не входимые оболочки, входимы единицы, и это **читается игроком**.

- **Тир-0 «руина-оболочка»** — подавляющее большинство. Декор, **не входимые, без
  интерьера и интерактива**. Генерируются процедурно из футпринта. **Руками не трогаем.**
- **Тир-0.5 «полу-входимый»** — третий дешёвый тип. Двор / навес / крыльцо / частично
  обрушенный корпус: можно зайти в зону, укрыться от ветра, подобрать мелочь — **но
  полноценного интерьера и укрытия нет**. Дёшев: футпринт + немного открытой геометрии,
  без авторского интерьера. Даёт разнообразие и «почти-укрытие» без затрат.
- **Тир-1 «живой дом»** — курированный набор, **5–7 на район**. Входимый, чинится,
  кандидат в укрытие. Ручная авторская работа по шаблону укрытия на Fort Street.

**Как назначается тир (дёшево и детерминированно):**
- Тир-1 = правило + ручной список: целый футпринт нужного размера, не на воде/льду,
  распределён по району. Часть зданий — Тир-0.5, всё остальное автоматически Тир-0.
- Бюджет авторской работы ограничен: район × (5–7 домов), а не 12 354 объекта.

**Процедурная разруха Тир-0 (бесплатно, детерминированно от seed + футпринта):**
- **сгоревший** — обугленный материал, нет крыши;
- **обрушенный** — просадка/наклон массинга;
- **заметённый** — снежная шапка по высоте массинга;
- **доли — поровну, без привязки к маршруту** (единого маршрута нет никогда — см. §7);
- вариативность по seed, чтобы город читался мёртвым и разным без ручного труда.

**Почему это правильно:**
- **Грамматика:** Тир-1 дома = «укрытие как глагол» (кандидаты в укрытие); разруха =
  почему мир опасен, без боевых врагов.
- **План:** это шаг 6 (читаемость маршрута) и питает §8 (география укрытий).
- **Бюджет:** масса создаёт образ замёрзшего мёртвого города; работаешь ты с горсткой домов.

- **[game]** Бюджет Тир-1: **5–7 домов на район** (решено).
- **[game]** Состояния Тир-0: сгоревший / обрушенный / заметённый, **доли поровну, без
  привязки к маршруту** (решено).
- **[game]** Третий тип — **Тир-0.5 «полу-входимый»** — включён (решено).

## Приложение A. Открытые источники для пайплайна сборки

**Принцип.** Карта бедна атрибутикой (мало деревьев/кустов, нет цветов домов и вывесок).
Всё, что можно вынести из открытых данных — выносим **офлайн-билдерами** в снапшот
`data/world/key_west/` и/или в Blender-разброс; **рантайм-загрузчика нет** (как в
`WORLD_PROFILES.md`). Приоритет — «дешёвая масса» без ручного труда (та же логика §5).

**Три самых сильных выигрыша (сделать первыми):**
1. **Деревья из лидара** — классификация растительности в point-cloud → Canopy Height
   Model → авто-расстановка деревьев с реальными высотами. Масса зелени без рук.
2. **Цвета домов из ортофото** — сэмплинг цвета крыш/фасадов из NAIP там, где нет тегов
   → достоверно «пёстрые дома» на все здания, без ручной покраски.
3. **Вывески из POI** — имена/категории Overture places + OSM → тексты табличек/баннеров
   (бар, дайв-шоп, отель) — характер Ки-Уэста.
