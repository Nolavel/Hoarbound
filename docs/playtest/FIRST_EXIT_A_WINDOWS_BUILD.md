# First Exit A — первый проверочный Windows x64 билд

**Статус: подготовка, НЕ подтверждённый рабочий экспорт.** Владелец запросил ранний небольшой внешний тест существующей игры, раньше будущего массового плейтеста и до «publisher-ready» vertical slice. Не расширять механику и мир; исправлять только связи, мешающие **реальному прохождению First Exit**.

**Что передаём:** архив с запуском Hoarbound для Windows x64, который человек открывает **без Godot, исходников, GitHub и редактора**. Ни Steam, ни инсталлятор, ни большой выпуск пока не нужны. Игрок должен пройти Battery Osceola → 727 Fort Street → сон → сохранение → перезапуск/Continue.

Актуальный маршрут и живой протокол наблюдения: [FIRST_EXIT_A_RUN.md](FIRST_EXIT_A_RUN.md). Production-трекер: [issue #42](https://github.com/Nolavel/Hoarbound/issues/42). Приоритеты/решения: Miro «Hoarbound Production Desk»; реализация: GitHub.

## Порядок работ без новых механик

**0. Инвентаризация пути игрока.** Сопоставить все реальные интерактивные объекты/слоты в доступной части мира с их action, UI, владельцем состояния и сохранением: движение, камера, дверь, поиск/подбор, несение/сброс, Hub/Quick Access, инструменты, ремонт проёмов, печь, тепловые зоны, еда/вода, отдых/сон, погода/потребности, компас/достижение, save/load. Для необязательных объектов пути также проверить, что они не вызывают софтлоков. Зафиксировать `PASS / FAIL / НЕ ПРОВЕРЕНО`; не переносить исправление на новый manager.

**1. Дешёвые автоматические гейты.** Reuse `tools/ci/import_gate.sh`, `tools/ci/run_tests.sh`, существующие `tests/systems` и `.github/workflows/checks.yml`. У `suites.yml` есть режим **report-only** и перечень известных падающих тестов: зелёный основной gate не означает, что весь gameplay прошёл. Целевые тесты выбирать из уже существующих; рендер CI не запускать серией мелких правок.

**2. Real-scene smoke в редакторе.** Пройти **от Battery Osceola**, а не teleport-to-727, без TestScene и подставных предметов; проверить ручные взаимодействия и обходы отказа: предмет занял обе руки, занятый слот, уход от действия, отмена/повторное взаимодействие, возвращение в дом, последовательное открытие/закрытие Hub. Зафиксировать лог и скриншот важных проблем. Scripted-тесты отдельно.

**3. Windows export preflight.** На машине сборки установить **Godot 4.8-dev6 .NET/Mono**, его **совпадающие по версии export templates**, .NET 8 SDK (ориентир проекта `global.json`) и зависимости, реально необходимые этой сборке. Проверить, что чистое открытие, импорт и компиляция проекта проходят. Не менять версию движка ради экспорта без решения автора.

**4. Windows Desktop preset.** В Godot: **Project → Export → Add → Windows Desktop**; x86_64, обычный release. Имя пресета сохранить `Windows Desktop` в `export_presets.cfg` и закоммитить после ревью (без ключей/паролей). Не встраивать PCK без необходимости; для Windows это может мешать подписи и создавать ложные срабатывания антивирусов. Исключать из финального пакета editor-only инструменты, **но не исключать игровые ресурсы наугад**: для этого проверить реальные зависимости export. Пока пресета нет, готовой повторяемой сборки **нет**.

**5. Экспорт.** Создать директорию **за пределами репозитория** (например `../Hoarbound-FirstExit-A/`) и экспортировать проект через меню Godot. После появления и проверки пресета можно повторять CLI:

```powershell
# Из каталога проекта, при установленном Godot .NET editor и export templates:
New-Item -ItemType Directory -Force ..\Hoarbound-FirstExit-A | Out-Null
godot --headless --path . --export-release "Windows Desktop" "../Hoarbound-FirstExit-A/Hoarbound.exe"
```

CLI-команда — **документированный порядок для будущего пресета**, не отчёт об успешном экспорте. Содержимое каталога после успешного export проверять фактически: `.exe`, игровой пакет и все необходимые `.dll`/`.json`/runtime-файлы. Архивировать **целую** выходную директорию, не один `.exe`. SHA исходного commit и версию Godot записать в заметку к архиву.

**6. Чистая Windows-проверка.** Распаковать в новую папку на Windows x64 и запустить **без открытого Godot-редактора**, желательно на другом компьютере. Проверить: старт у Battery Osceola; управление и курсор; читаемость UI при 1080p и меньшем разрешении; звук; доступность 727; реакции всех обязательных предметов; выход из игры и новый запуск; Continue; сохранение pickup/инвентаря/убежища/огня/погоды. Отдельно записать GPU/драйвер, режим Vulkan, FPS и зависания. Проблемы с `.NET`, отсутствующей библиотекой или пустыми ресурсами = **P0**.

**7. Проверка сторонним человеком.** Только после P0-прохождения автором; тестер не должен устанавливать Godot и не должен знать внутреннюю карту/инструменты. Использовать [протокол](FIRST_EXIT_A_RUN.md); один непрерывный свежий проход и последующий запуск из сохранения. Архив и отчет — **закрытые**, не массовая публичная демоверсия.

## Минимальный пакет и артефакты проверки

- `Hoarbound.exe` и **все** файлы, созданные/необходимые Godot .NET Windows export, сохранённые с исходной структурой.
- `README_TESTER.txt` — запуск, базовые клавиши при отсутствии читаемой подсказки, запись ошибок и где найти лог; без сюжетных подсказок.
- `BUILD_INFO.txt` — SHA, Godot, дата, target Windows x64, тип экспорта, подготовивший и проверивший.
- Отчёт разработчика: логи гейтов, export log, SHA-256 ZIP, первые screenshot/запуск на другом ПК, итог `PASS / FAIL / NOT TESTED`.

**Гейт «можно отправить первому тестеру»:** один реальный Windows standalone стартует с Battery Osceola; нужные взаимодействия ведут к ночлегу, игра сохраняет/загружает согласованное состояние, нет известных P0; не нужен Godot и нет developer UI. Визуальный полиш и будущий массовый плейтест — **следующая стадия**, а не условие первой технической проверки.

Официальные инструкции Godot: [экспорт проектов](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_projects.html), [Windows](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_windows.html), [командная строка](https://docs.godotengine.org/en/4.5/tutorials/editor/command_line_tutorial.html). Поведение конкретного `4.8-dev6` нужно проверить на установленном движке.
