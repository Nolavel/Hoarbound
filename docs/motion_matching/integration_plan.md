# Motion Matching — integration plan (proposal, not merged)

Status: experimental lab on `claudeflow` (#202). Production locomotion
(`HenryUALAnimation` + `MovementController` + `RotationController`) is untouched
and stays the default.

## Runtime ownership (as proven in the lab)

```text
player intent (MovementController / RotationController)
        │  desired velocity, desired facing
        ▼
CharacterBody3D  ── authoritative position/rotation, collisions
        │
        ▼
MotionMatchingDatabasePlaybackController
  query  = live Henry pose (skeleton) + simulation future (0.2/0.5/0.8 s)
  search = all real frames (range tails and playing neighbourhood skipped)
  play   = two advancing slots, crossfade on accepted switch
  root   = animated root follows the body: root motion + velocity-limited
           adjustment (halflife 0.1 s / 0.2 s, ≤ 50% of own speed) + clamp
           (0.15 m, 90°)
        ▼
HenryUALVisual transform + Skeleton3D local rotations / pelvis position
```

In the lab `MotionCharacterSimulation` stands in for the production
controllers. In the game the body already moves; the controller would read
`velocity` and the facing goal instead of owning the springs.

## Proposed integration layer

1. `MotionMatchingLocomotion` node, child of `Player`, `@export var enabled`.
   When disabled it does nothing and `HenryUALAnimation` keeps full control.
2. When enabled it switches off the locomotion part of the AnimationTree
   (actions, carry, sit and work poses keep their current owner and pre-empt
   Motion Matching), feeds the controller from `MovementController` intent,
   and writes only the skeleton pose and the visual root offset.
3. The baked database becomes a project resource derived from CMU (free for
   all uses), regenerated by `audit_motion_dataset.gd`; raw BVH stays out of
   Git. Current size: ~9.2 k samples ≈ 11 MB uncompressed.
4. Search moves to C# only if profiling on the target hardware asks for it
   (GDScript brute force here: ~7 ms per search over 9.2 k samples, one
   search per 0.1 s).

## Not yet covered

- Foot locking / IK on contact. Pure playback reproduces the data's own
  planted-foot slide (0.075 m/s on forward walking); frequent switches and
  root adjustment raise it to ~0.18 m/s over the proof.
- Run/jog, crouch, carry, slopes and stairs domains.
- Inertialization instead of crossfade.
- 100STYLE or other diagonal-rich material (forward diagonals are thinnest).
